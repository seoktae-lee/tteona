chmod 400 ~/Downloads/에어론\ 펨키/aeron-web-key.pem chmod 400 ~/Downloads/에어론\ 펨키/aeron-was-key.pem chmod 400 ~/Downloads/에어론\ 펨키/aeron-db-key.pem

코스 추천 엔진

⏱ 1~2주 WAS + DB 서버
🎯 비유: 넷플릭스 추천 알고리즘
지금은 좋아요 많은 순서로 나열하는 "베스트셀러 진열대"입니다. 이 단계에서는 사용자가 어디 있는지, 어떤 코스를 좋아했는지, 지금 계절이 무엇인지를 보고 "이 사람에게 딱 맞는 코스"를 추천하는 개인화 엔진을 만듭니다.
스코어링 기반 추천 API 구현 (GET /api/courses/recommend)
인기도(40) + 신선도(25) + 현재위치 근접(25) + 태그선호(10) 가중합 점수 계산. PostgreSQL recommendation_cache 5분 TTL 캐싱. iOS MainView에 ⚡(나루) 추천 필터 버튼 추가.
1순위 — 시즌 추천 (봄 벚꽃, 여름 해변, 가을 단풍, 겨울 야경)
신규 UI 불필요. 기존 스코어링 공식에 시즌 가중치 +10점 추가 (코스 태그/장소명에 계절 키워드 매칭). 서버만 수정, 배포 즉시 탐색 탭 "추천순"에 반영. 예상 반나절.
2순위 — 이번 주 TOP 10 코스 (매일 자정 Cron으로 재계산)
탐색 탭 "인기 크리에이터" 스트립 아래 같은 패턴의 가로 카드 스트립 추가. 서버는 node-cron 자정 재계산 + PostgreSQL 캐싱. 예상 1~2일.
3순위 — 탐색 탭 검색바 (코스명/지역명 검색)
추천 엔진과 별개 기능. 홈탭(지도 중심)이 아닌 탐색 탭 상단에 배치 — 코스 발견 맥락과 일치. 예상 1~2일.
4순위 — 협업 필터링 추천 (좋아요 데이터 축적 후)
"이 코스 좋아한 사람들이 좋아한 다른 코스" — ExploreDetailView 하단 섹션으로 배치. 현재 좋아요 데이터가 적어 효과 미미, 유저 늘어난 뒤 진행.

WebSocket 실시간 위치 공유 + 채팅

⏱ 1~2주 WAS 서버
📡 비유: 전화 vs 편지
지금 Firestore 방식은 "편지를 보내고 상대방이 읽기를 기다리는 것" (3~5초 지연). WebSocket은 "전화처럼 연결이 항상 열려있어서" 위치 변화가 즉각 전달됩니다. 이 연결을 이용해 채팅도 함께 구현할 수 있습니다.
ws 기반 WebSocket 서버 구현 (/ws/location)
WAS에 ws npm 패키지 추가. roomId 기반 브로드캐스트, 30초 heartbeat, 연결 해제 시 자동 정리. Nginx /ws/ 프록시 블록 추가 (Upgrade 헤더).
실시간 위치 공유 Firestore → WebSocket 전환 완료
LocationSocketService.swift 신규 생성. ActiveSessionView에서 Firestore 위치 리스너 제거, WebSocket connect/sendLocation/disconnect로 교체. 지연 3~5초 → 50~200ms.
그룹 실시간 채팅 (단톡·푸시·답장·이모지반응) — 서버 배포 완료
