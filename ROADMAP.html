SSH 접속 확인

⏱ 30분 전체 서버
🔑 비유: 새 사무실 열쇠 받기
공사가 끝난 사무실(서버)에 처음 들어가는 것. 열쇠(PEM 키)로 문을 열고 불이 켜지는지, 수도가 나오는지 기본 확인하는 단계입니다.
PEM 키 권한 설정
PEM 키 파일 권한 설정 (최초 1회)
권한이 너무 열려있으면 SSH가 거부함. 반드시 먼저 실행.
chmod 400 ~/Downloads/에어론\ 펨키/aeron-web-key.pem chmod 400 ~/Downloads/에어론\ 펨키/aeron-was-key.pem chmod 400 ~/Downloads/에어론\ 펨키/aeron-db-key.pem
서버 접속 테스트
WEB 서버 접속
ssh -i ~/Downloads/에어론\ 펨키/aeron-web-key.pem -p 30022 ubuntu@114.110.182.45
WAS 서버 접속
ssh -i ~/Downloads/에어론\ 펨키/aeron-was-key.pem -p 30022 ubuntu@114.110.181.49
DB 서버 접속
ssh -i ~/Downloads/에어론\ 펨키/aeron-db-key.pem -p 30022 ubuntu@114.110.183.183
접속 후 root 권한 상승 확인
sudo -i

코스 공유 OG 링크

⏱ 3~5일 WEB 서버 🔥 홍보 효과

WAS API 서버 구축 + Places 캐시 이전

⏱ 1주 WAS + DB 서버 💰 즉각 비용 절감
🏭 비유: 공장 가동 시작
지금까지는 사무실(WEB)과 창고(DB)만 세팅했습니다. 이제 실제로 일을 처리하는 공장(WAS)을 가동하는 단계. iOS 앱이 이 공장에 주문을 넣으면 공장이 DB에서 재료를 꺼내 처리해서 돌려줍니다.

Google Places 캐시 이전은 이 단계에서 함께: "매번 편의점에 사서오던 재료를 이제 대형 냉장고에 사다 놓는 것" → 재료비(API 비용) 80% 절감.
Node.js API 서버 초기 구성
Express.js 기반 API 서버 프로젝트 생성
라우터, 미들웨어, Firebase Admin SDK 연동 설정
PM2로 서버 상시 실행 + 자동 재시작 설정
서버 재부팅되어도 자동으로 앱이 다시 켜짐
pm2 start app.js --name tteona-api pm2 startup # 재부팅 시 자동 실행 등록 pm2 save
Nginx → WAS 프록시 설정
api.tteona.kr 또는 tteona.kr/api 요청을 WAS로 전달
Google Places 캐시 PostgreSQL 이전
Places 캐시 API 엔드포인트 구현
GET /api/places/cache?key=xxx (PostgreSQL 조회) + POST /api/places/cache (저장). write-through 패턴으로 iOS가 Google API 결과를 WAS에 저장.
iOS 앱에서 Firestore 직접 캐시 대신 WAS API 호출로 변경
PlaceDetailService.swift 캐시 순서: 메모리 → PostgreSQL(WAS) → Firestore → Google Places API. 결과는 WAS + Firestore 둘 다 저장.
