## PART 1. 보안 점검

### 잘 되어 있는 것 (유지)

- 전 API `requireAuth` — Firebase ID 토큰 검증, 클라이언트 userId 불신 원칙
- WebSocket join 시 토큰 검증 + 방 멤버십 확인, 실패 코드 분리(4001/4003)
- BGM 파일 라우트 path traversal 방어 (`normalize` + `startsWith`)
- 관리자 로그인 브루트포스 리미터 (IP당 15분 5회)
- CORS 화이트리스트 (tteona.kr만), helmet, 업로드 크기 제한(10MB/300MB)
- 시크릿 환경변수 강제(fail-fast) + 노출 이력 로테이션 완료
- Firestore rules: 필드 단위 diff 검증(isVerified 보호), 방 멤버십 기반 접근, reports/fcmRequests 쓰기 전용
- Vlog job 소유권 검증(requireJobOwner), FFmpeg 타임아웃 SIGKILL
- 계정 삭제 시 제공자별 연쇄 정리 (Apple revoke, Kakao unlink, PG purge)

### 🔴 S1. `trust proxy` 미설정 — 브루트포스 방어 무력화

`server.js`에 `app.set('trust proxy', ...)`가 없다. Nginx 뒤에서 `req.ip`는 항상 **프록시 내부 IP 하나**로 잡힌다. 결과:
- 공격자 관점: 리미터가 모든 요청을 한 IP로 집계하므로, 정상 유저의 실패와 섞여 사실상 IP별 차단이 아님.
- 정상 유저 관점: 누군가 5회 실패하면 **전 세계 모두가 15분간 관리자 로그인 차단** (DoS 표면).

**조치**: `app.set('trust proxy', 1)` (nginx 1홉 신뢰) + nginx에서 `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;` 확인. 배포 후 `req.ip`가 실제 클라이언트 IP인지 로그로 검증.

### 🔴 S2. Firestore `likeCount` 무제한 조작 가능

규칙이 "타 유저는 likeCount 필드만 수정 가능"까지만 검증하고 **값의 증분을 검증하지 않는다**. 아무 로그인 유저나 임의 코스의 likeCount를 9,999,999로 설정 가능. 좋아요 수는 정렬·추천·크리에이터 랭킹의 근거라 **조작 유인이 실재**한다.

**조치(택1)**:
- 규칙에 증분 검증 추가: `request.resource.data.likeCount == resource.data.likeCount + 1 || request.resource.data.likeCount == resource.data.likeCount - 1`
- 또는 좋아요를 서버 API(검증된 uid 기준 likes 서브컬렉션 + 집계)로 이전 — 중복 좋아요 방지까지 해결되므로 장기적으로 이쪽 권장.

### 🟠 S3. `placeCache` 컬렉션 전체 유저 read/write — 캐시 오염

로그인 유저 누구나 placeCache 문서를 임의 내용으로 덮어쓸 수 있다 → 조작된 장소 정보/사진이 **전체 유저에게 서빙**될 수 있음 (저장형 XSS급 파급). 장소 캐시가 PG로 이전 완료됐다면 이 컬렉션은 유물이다.

**조치**: 앱이 더 이상 안 쓰면 `allow read, write: if false;`로 잠그고 데이터 삭제. 아직 쓰면 write를 서버(Admin SDK) 전용으로.

### 🟠 S4. 일반 API 레이트리밋 부재

리미터가 관리자 로그인에만 있다. 인증된 계정 하나로 Vlog job 생성·300MB 업로드·푸시 발송 트리거를 무한 반복 가능 — 디스크/CPU 고갈 벡터.

**조치**: `express-rate-limit`으로 전역 기본(예: IP당 분당 120) + 고비용 라우트(vlog jobs, 업로드, 푸시) 별도 강화. 무료/PRO별 일일 Vlog 생성 한도를 **서버에서도** 검증 (현재 앱 게이팅만 있다면 우회 가능).

### 🟠 S5. ADMIN_TOKEN이 정적·무만료

로그인 성공 시 항상 동일한 고정 토큰을 반환한다. 한 번 유출되면(브라우저 localStorage, 로그 등) 로테이션 전까지 영구 관리자 권한.

**조치**: 로그인 시 만료 있는 세션 토큰 발급(랜덤 생성, 메모리/PG 저장, 24h 만료)으로 전환. 최소한 ADMIN_TOKEN 주기적 로테이션 운영 수칙이라도.

### 🟡 S6. 기타 (계획적 개선)

- `adminLoginAttempts` Map 무한 성장 (만료 엔트리 청소 없음) — 주기 정리 추가
- WS `location` 메시지의 lat/lng 타입 검증 없음 — 숫자 검증 후 브로드캐스트
- Google Maps/Places API 키: 콘솔에서 **번들 ID·API별 제한** 걸려 있는지 확인 (앱에 키가 내장되는 구조는 불가피 — 제한이 유일한 방어)
- TLS 인증서 자동 갱신(certbot cron) 여부 서버에서 확인
- PG 백업 부재 — 보안이라기보다 생존 문제. pg_dump 야간 크론 + 타 서버 복제 (로드맵 Phase 1과 동일)
- iOS `Color(hex:)`의 Scanner는 방어적이므로 문제없음. 앱 내 하드코딩 시크릿은 발견되지 않음 (Google 키는 plist 관례 — 위 콘솔 제한으로 방어)

## PART 2. 법적 리스크 점검

### 🔴 L1. 위치정보법 — 위치기반서비스사업 신고

떠나는 **개인위치정보를 수집·이용하는 위치기반서비스**(도착 감지, 실시간 위치 공유)다. 위치정보법상 위치기반서비스사업자는 방송통신위원회 **신고** 대상.

- **소상공인·1인 창조기업 특례**(위치정보법 제9조의2): 신고 없이 개시 가능하나, 요건·규모를 벗어나면 지체 없이 신고해야 함. 특례 적용 대상인지 확인하고, **KISA 인프라로 요건이 갖춰진 지금 정식 신고를 진행하는 것을 강력 권장** (지원사업 성과보고에도 유리).
- 신고 시 필요한 것: 이용약관(위치정보 조항), 위치정보 보호조치 명세 — 현재 terms.html 8조가 골격이나, 신고 서식에 맞춘 보완 필요.

### 🔴 L2. 개인위치정보 수집 '동의' 절차

위치정보법 제19조: 위치기반서비스 제공자는 **이용약관에 위치정보 관련 사항을 명시하고 동의**를 받아야 한다. iOS 위치 권한 팝업(OS 권한)과 **법적 동의(약관 동의)는 별개**다.

**확인/조치**: 온보딩의 약관 동의 화면에 "위치기반서비스 이용약관" 동의 항목이 **별도 체크박스**로 분리되어 있는지 확인. 통합 동의라면 분리 권장 (선택 아닌 필수 동의로 두되, 항목은 구분 표기).

### 🟠 L3. 개인정보 국외 이전 고지 (개인정보보호법 제28조의8)

Firebase(미국 Google), RevenueCat(미국) 사용 = **개인정보 국외 이전·처리위탁**. 개인정보처리방침에 ① 이전되는 항목 ② 이전 국가·시기·방법 ③ 이전받는 자(연락처) ④ 이용 목적·보유 기간을 명시해야 한다. → **8번 과제에서 privacy.html에 반영**.

### 🟠 L4. 만 14세 미만 아동

만 14세 미만 수집 시 법정대리인 동의 필요. 현실적 대응은 **가입 시 만 14세 이상 확인**(생년 입력 또는 확인 체크) + 약관에 "만 14세 미만 이용 불가" 명시. 아동안전정책 페이지는 이미 있으나 가입 플로우의 연령 확인 장치 여부 확인 필요.

### 🟠 L5. BGM 저작권 — 놓치기 쉬운 큰 리스크

서버 `assets/bgm`의 음원이 Vlog에 **합성되어 유저 SNS로 재배포**된다. 이는 단순 스트리밍보다 넓은 이용 범위(복제·배포·2차적 저작물)다.

**조치**: 각 트랙의 라이선스를 표로 문서화(출처·라이선스·상업적 이용·재배포·크레딧 의무). 크레딧 표기 의무가 있는 트랙은 Vlog 엔딩 크레딧 또는 앱 내 고지에 표기. 불명확한 트랙은 교체 (Pixabay Audio·Mixkit 등 상업적 이용+재배포 허용 소스로).

### 🟠 L6. 전자상거래 관련

- **통신판매업 신고**: PRO 구독 판매 주체 이슈. 국내 관행상 유료 앱 서비스 운영자는 통신판매업 신고를 하는 것이 안전 (간이 면제: 직전연도 거래 횟수 50회 미만 등). 사업자등록과 함께 준비 권장.
- **구독 필수 고지**: 청약철회·환불 조건, 자동갱신 고지 — 현재 약관에 구독 조항 있는지 확인 → 8번 과제에서 보강.
- **부가통신사업자 신고**: 자본금 1억 원 이하는 신고 간주(면제) — 해당될 가능성 높음, 참고만.

### 🟡 L7. 기타

- **TourAPI 이용조건**: 한국관광공사 출처 표기 의무 확인 — 장소 사진에 출처 라벨 or 앱 내 고지 페이지에 명시
- **UGC 대응 체계**: 신고 접수→처리 기록 보존 (관리자 대시보드 있음 — 처리 이력 로그만 남기면 충분)
- **표시광고법**: 인플루언서 협찬 시 경제적 대가 표기 (OUTREACH_EMAILS.md에 반영됨)
- **해외 배포**: en/ja 지원 — 일본 APPI·GDPR은 해당 지역 '타겟팅' 시 적용. 스토어 배포 지역을 의도적으로 관리하고, EU 본격 진출 전까지는 현 수준 고지로 족함
- **청소년보호책임자 지정**: 일평균 이용자 10만 명 이상 시 의무 — 현 단계 해당 없음 (도달 시 대응)
