## 1. 촬영 성공 문구 실종 (회귀 버그)

**원인** — 무료 유저 5초 자동 종료 경로에서 성공 오버레이가 안 뜬다.
- 녹화 종료를 CameraService가 sample-time 기준으로 직접 수행하도록 리팩토링(첫 클립 잘림 수정)하면서, UI 쪽 `stopRecordingUI()`(= `savingOverlay`를 켜는 유일한 코드)는 벽시계 `clipLimit + 1.5s` 백업 타이머로 밀려 사실상 호출되지 않게 됨.
- `CameraView.swift`의 `showSaveSuccessAndClose()`는 오버레이 **내부의** 인디케이터/체크마크만 토글하고 `savingOverlay.isHidden = false`는 하지 않음 → 오버레이가 숨겨진 채로 체크마크만 바뀌고 1.2초 후 화면이 닫힘.
- PRO 유저(탭으로 종료 → `stopRecordingUI()` 경유)는 정상 → "어느 순간 안 뜨네"의 정체.

**수정** — `CameraView.swift:683` `showSaveSuccessAndClose()` 첫 줄에 `savingOverlay?.isHidden = false` 추가 (+ `view.isUserInteractionEnabled = false`는 이미 stopRecordingUI에서만 하므로 자동 종료 경로에서도 문제없는지 확인). 촬영 완료는 Haptics 사용 목록에 있으므로 `Haptics.success()`도 이 시점에 추가.

**파일**: `tteona/Features/Camera/CameraView.swift`

## 3. Vlog 서버 합성 실패 → BGM·워터마크 없는 로컬 폴백

**구조** — `VlogGenerationView`: 서버(WAS FFmpeg) 합성 1순위, **어떤 에러든** throw되면 조용히 로컬 AVFoundation 폴백. 로컬 폴백에는 BGM·워터마크·타이틀카드가 전부 없음 → 사용자가 목격한 증상.

**실패 트리거 (가능성 순)**
1. **화면 자동잠금**: `isIdleTimerDisabled` 미설정. 생성은 수 분 걸리는데 화면이 잠기면 앱 suspend → foreground URLSession 요청 실패 → 폴백. 유력한 최다 원인.
2. **폴링 무관용**: `VlogServerService.generate()`의 status 폴링(2초×900회)이 **단 1회** 실패해도 전체 포기. 셀 전환·일시적 끊김에 취약. 서버는 멀쩡히 렌더링을 끝내는데 폰은 로컬 폴백을 중복 수행.
3. **업로드 무재시도**: 클립 1개 업로드 실패 = 전체 실패.
4. jobId를 어디에도 보존 안 함 → 실패 후 서버 완성본(푸시 `vlog_done`까지 옴)을 받을 방법이 없음.
5. 서버측 진짜 실패(ffmpeg exit/timeout)는 `vlog_jobs.error_msg`에 남지만 아무도 안 봄.

**수정 설계 (성공률 ~100% 목표)**
1. `generatingView` 진입 시 `UIApplication.shared.isIdleTimerDisabled = true`, 종료(preview/error/onDisappear) 시 해제.
2. 폴링 내성: 연속 실패 카운터 도입 — 연속 ≤10회(약 20초)까지는 에러 무시하고 계속 폴링, 초과 시에만 포기.
3. 업로드 재시도: 클립당 2~3회 지수 백오프.
4. jobId를 UserDefaults에 영속화(`sessionId`와 함께). 실패·앱재시작 후 재진입 시 서버 상태 먼저 조회 → `completed`면 다운로드만 수행. `vlog_done` 푸시 탭 → 같은 복구 플로우.
5. **로컬 폴백 조건 축소**: 서버가 명시적으로 `failed`를 반환했거나, 업로드가 재시도 후에도 불가한 경우에만 폴백. 폴백 시 "네트워크 문제로 기본 버전(BGM 제외)으로 저장했어요" 토스트로 고지 — 지금은 무통보라 품질 저하가 랜덤 버그처럼 보임.
6. 관측성: 폴백 발생 시 사유를 서버 `/api/log`(신설) 또는 Firestore에 적재. 서버 `vlog_jobs` failed 잡 주간 점검.
7. (선택) 업로드/다운로드를 background URLSession으로 전환하면 백그라운드 전환에도 완전 내성 — 공수 크므로 2차.

**파일**: `tteona/Features/Vlog/VlogGenerationView.swift`, `tteona/Core/Services/VlogServerService.swift`, (서버) `server.js`

## 4. 채팅방 키보드가 최신 메시지 가림

**원인** — `GroupChatView.swift`: 키보드가 올라오면 ScrollView 높이만 줄고 스크롤 보정이 없음. `inputFocused` 변화나 키보드 노티에 대한 `scrollTo("BOTTOM")` 부재.

**수정** — 두 가지 병행:
1. ScrollView에 `.defaultScrollAnchor(.bottom)` (iOS 17+, 프로젝트는 이미 iOS 17 API 사용 중) — 채팅처럼 바닥 기준 콘텐츠에 정석. 키보드 등장으로 뷰포트가 줄어도 바닥 앵커 유지.
2. 보강: `.onChange(of: inputFocused)`에서 `true`가 되면 0.1~0.3초 후 `proxy.scrollTo("BOTTOM", anchor: .bottom)` (키보드 애니메이션과 동기화).

**파일**: `tteona/Features/Group/GroupChatView.swift`

## 5. 탐색탭 pull-to-refresh 시 인기 크리에이터 사라짐

**원인** — 이중:
1. `StatsService.fetchCreatorRanking()`이 실패(네트워크 오류 **또는 SwiftUI가 `.refreshable` 태스크를 취소**한 경우) 시 `[]`를 반환하고, `ExploreGridView.loadAll()`이 이를 그대로 `creatorRanking`에 대입 → `if !creatorRanking.isEmpty` 조건으로 스트립이 통째로 사라짐. `.refreshable`은 당김 제스처 종료·뷰 갱신 시 태스크를 취소하는 것으로 악명 높음 → "쭉 댕기면 일시적으로 사라진다"와 정확히 일치.
2. 실시간성: 서버 `/api/creators/ranking`은 PG 캐시 10분(`recommendation_cache`) → 당겨도 좋아요/순위가 바로 안 바뀜.

**수정**
1. `fetchCreatorRanking()` 반환형을 `[CreatorRank]?`로 — 실패 시 `nil`. `loadAll()`에서 `nil`이면 기존 값 유지(빈 배열 덮어쓰기 금지). 코스/썸네일도 같은 원칙 적용 검토.
2. `.refreshable { await Task { await loadAll() }.value }` 패턴으로 취소 전파 차단(비구조화 태스크로 감싸기).
3. 서버 랭킹 캐시 10분 → 2분으로 단축 (Firestore 읽기 500 docs × 30회/시간 수준이라 비용 무시 가능). 좋아요 수는 코스 fetch에서 이미 실시간이므로 카드의 ♥는 즉시 반영됨.

**파일**: `tteona/Core/Services/StatsService.swift`, `tteona/Features/Explore/ExploreGridView.swift`, (서버) `server.js:613` 캐시 TTL

## 6. 인증마크 부여 — admin 비밀번호와 운영 방식

**"tteona-admin 비밀번호"** — 코드베이스에 `tteona-admin` 계정은 없음. 실체는 **tteona.kr 관리자 대시보드**(`tteona-web/admin/index.html`) 로그인 비밀번호로, WAS 서버 환경변수 `ADMIN_PASSWORD`(`/home/ubuntu/tteona-api/.env`)에 있음. 로컬에는 저장 안 돼 있음. 확인:
```bash
KEYDIR="$HOME/Downloads/2026 클라우드 인프라 지원 사업 선정/260701/에어론 펨키"
ssh -i "$KEYDIR/aeron-was-key.pem" -p 30022 ubuntu@114.110.181.49 "grep ADMIN /home/ubuntu/tteona-api/.env"
```

**현재 인증마크** — Firebase 콘솔에서 `users/{uid}`의 `isVerified: true` + `creatorLabel: "developer"`를 수동 편집. admin API에는 block/unblock만 있고 verify 엔드포인트 없음.

**타 서비스** — 인스타그램: 신청 양식 → 내부 심사(유명성·진정성 기준) + Meta Verified 유료 구독 병행. X/틱톡도 유사(구독 또는 내부 심사). 공통점: **자체 어드민 도구로 부여**하지 DB 콘솔을 직접 만지지 않음.

**권장** — 현 규모에서 수동 부여 정책 자체는 적절. 단 Firebase 콘솔 직접 편집은 오타·실수 위험이 있으니 기존 admin 대시보드에 통합:
1. 서버: `POST /api/admin/users/:uid/verify` — body `{ verified: bool, label: string|null }` → users 문서 갱신 (`adminAuth` 재사용, block/unblock 옆에 추가).
2. 대시보드: 유저 테이블에 인증 상태 컬럼 + "인증 부여/해제" 버튼 + 라벨 입력.
3. (선택) 크리에이터 랭킹 상위 유저를 후보로 노출해 원클릭 부여.

**파일**: `server.js` (admin API 섹션), `tteona-web/admin/index.html`

## 7. 다국어 — 지도 라벨·코스 제목(UGC) 미번역

**원인 2갈래**
1. **지도 라벨**: `GMSMapView`는 프로세스 로케일(`AppleLanguages`) 기준으로 타일 라벨을 그림. `LanguageManager`는 자체 UserDefaults 키(`app.language`) + 번들 스왑만 하므로 지도 SDK에는 전달 안 됨. Google Maps iOS SDK는 런타임 언어 오버라이드 API가 없음.
2. **코스 제목·장소명**: 유저 생성 콘텐츠(UGC)라 정적 번역 불가. Kakao 검색 장소명도 한국어 고정.

**수정 설계**
1. 지도: `LanguageManager.setLanguage()`에서 `UserDefaults.standard.set([code], forKey: "AppleLanguages")` 병행 저장 → **다음 실행부터** 지도 라벨이 선택 언어로. 언어 설정 화면에 "지도는 앱 재시작 후 적용" 안내 문구 추가. (실시간 적용은 SDK 제약상 불가 — 이것이 업계 표준 우회.)
2. 코스 제목(UGC): 서버 번역 프록시 권장 —
   - `GET /api/translate?text=&target=en|ja` → Google Cloud Translation(≈$20/1M자) 호출, PG `translation_cache` 테이블에 영구 캐시(제목은 불변에 가까움 → 캐시 적중률 매우 높음).
   - 클라: 앱 언어 ≠ ko일 때 탐색탭 카드·코스 상세 제목에 번역 적용(원문 병기 or "번역됨" 뱃지). 실패 시 원문 그대로.
   - 대안(비용 0): iOS 17.4+ Apple Translation framework 온디바이스 번역 — 단 Android 이식 불가라 서버 방식이 장기적으로 유리.
3. 장소명: Google Places Details가 `language` 파라미터 지원 → 기존 places_cache를 언어별 키로 확장하면 en/ja 공식 명칭 확보 가능(추가 과금은 캐시로 억제). Kakao 출처 장소는 번역 프록시로 처리.
4. 발자취 지역명은 `FootprintAtlas.nameEng` 이미 있음 — ja 추가 여부만 검토.

**파일**: `tteona/Core/Localization/LanguageManager.swift`, `tteona/Features/Settings/LanguageSettingsView.swift`, (서버) `server.js`, 탐색/상세 뷰
